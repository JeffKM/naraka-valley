# Slice 8 착수: 관계 심화 빌드 확정 — 선물 머신 풀·단계 관문·deed 게이트·연애/결혼/이혼 메카닉

> **갱신:** 2026-08-11 (Slice 8 착수 self-grill — Fable 5 자율 캠페인, 자문자답 변형).
> **이행:** [ADR-0032](./0032-relationship-gift-machine-deed-gate-marriage-subsystem.md)(선물 머신·deed 게이트·결혼 서브시스템)와 서사 바이블 §6.1~6.4(단계 관문·의지 시험·2단계 결혼)를 **빌드 가능한 결정으로 변환**한다. 설계 재론 아님 — 기확정 설계의 수치·구조·스코프 잠금.
> **불침범:** [ADR-0008](./0008-growth-model-relationship-multiplier.md) #1 평평≠막힘 · [ADR-0016](./0016-that-night-ensemble-seal-law.md) 봉인 법칙 · [ADR-0022](./0022-divorce-liberation-irreversible.md) 적대 없음 · [ADR-0029](./0029-cafe-relationship-stage-domain-aligned-rewards.md) 도메인 일치 · 서빙≠♡(ADR-0017 경계).
> **리서치 3축:** 코드 전수 감사(Explore/opus) · 스타듀 위키 미러 수치 대조(opus) · 설계 문서 계보 판독(sonnet) — 2026-08-11.

## 맥락

관계는 ADR이 가장 두껍게 깔린 영역(0008→0014→0016→0017→0021→0022→0029→0032)이라 self-grill의 본체는 새 설계가 아니라 **③변환**이었다: (a) 코드 감사가 밝힌 "이미 있는 것"(Affinity 노드·주민 11인 레지스트리·deed 원장 전량·세이브 관례) 위에 (b) ADR-0032가 확정한 골격(선물 머신 풀·deed 게이트·결혼)을 (c) 스타듀 위키 수치 대조로 보정해 얹는 결정들. 감사가 **실버그 1건**(관계 탭 6행 유실)과 **사장 상수 1건**(호감도 곡선이 폐지된 RUN_DAYS=21에 묶임)도 적발했다.

핵심 판독: 서사 바이블 §6.1의 "메인 호감도=활동 실적만" 절은 ADR-0032(2026-06-29)가 개정한 stale이다 — 현행 확정은 **"선물·일일 대화·활동 실적이 모두 하트를 채우고, 속죄 서사 진급만 deed 문턱을 추가 요구"**. 반면 §6.1의 **♡0~3=단계 관문 이벤트·♡4~5=의지 시험** 진급 구조와 §6.3의 **연애→결혼 2단계·정표=옥자의 혼례 부적**은 살아 있는 확정이며 이번 빌드의 뼈대다.

## 결정

### 1. 하트 스케일 ♡0~5 유지 · 곡선 상수 사장 참조 절단 · 감쇠 전면 폐지

- 스타듀 10/14하트 스케일은 **이식하지 않는다**. 기존 ♡0~5(MAX_HEARTS=5)가 전 시스템(HeartBar·카페 마일스톤·테스트)에 배선돼 있고, ADR-0032·서사 바이블이 이미 5-스케일로 표기(♡4≈스타듀 8하트 우정 종착·♡5≈10하트 연애). 결혼 후 미터 확장(스타듀 14하트)도 없음 — 결혼은 하트 위 **상태**다.
- `POINTS_PER_HEART`의 `RUN_DAYS=21` 파생(affinity.gd:41-44 ← summary.gd:32)은 S7이 폐지한 21일 런의 사장 상수다. **값(60점/칸·만렙 300점)은 유지하고 도출식만 명시 상수로 절단**(동작 불변·골든 안전). 현행 페이싱(대화 8+선물 주 2회 ≈ 2~3주/칸·♡5≈절기 3개)이 스타듀 페이싱(10하트≈시즌 2~3개)과 이미 근사함을 위키 대조로 확인.
- **감쇠(스타듀 −2/−10/−20/일)는 전면 비이식** — 관계를 유지비용 자원으로 만들어 ADR-0008 곱셈기 성격을 바꾸고, ADR-0029 "만성 스킵=당근만(감쇠 없음)"·코지 톤과 충돌.

### 2. 선물 머신 전면 — 든 아이템 문법 + 전역 선호 테이블 + 음수 채널

- **입력 경로 전환:** 선물 대상 = `inventory.selected_id()`(든 아이템) — 혼백관 기증과 같은 문법. 기존 `_selected_crop` 수확-작물 전용 경로(main.gd:15063-15081)는 폐지한다. 이 하나로 "물고기·광물·요리 선물 불가" 구조 제약과 옹이·풀무·무골 선호 미배정(실존 작물 5종 소진)이 동시 해소된다. G키 유지(칸 배타 기확인).
- **전역 선호 테이블 신설**(`gift_prefs.gd`): 스타듀 구조 이식 — **유니버설 계층**(러브/라이크/뉴트럴/디스라이크/헤이트, 카테고리 단위: 예 — 메뉴 요리=라이크·보석=라이크·debris 원자재=디스라이크·잡동사니=헤이트) 위에 **캐릭터별 개별 오버라이드**(러브 4~6종·헤이트 1~2종 — 스타듀 후보 중앙값 5~8 준용). 잠정 테이블은 캐릭터 결에서 파생하고, **실제 인물 취향 반영분(옥자님 소싱)은 owner 큐 1순위** — 테이블 데이터 교체만으로 반영(코드 0줄).
- **포인트(잠정):** 러브 +40(기존 GIFT_PREFERRED 승계) / 라이크 +25 / 뉴트럴 +15(기존 GIFT_POINTS 승계) / 디스라이크 −10 / 헤이트 −20. **음수(혐오) 채널 신설** — 실제 인물 혐오 반영은 ADR-0032 요청의 일부라 필수. 단 완만하고 영구 적대 없음.
- **품질 배율**(러브·라이크만) ×1/×1.1/×1.25/×1.5 — 스타듀 불변식 **"일반 품질 러브 > 이리듐 라이크"** 준수(40 > 25×1.5=37.5 ✓).
- **네오 선물 채널 개방**(can_gift=true) — "풀 T1 트랙은 후속" 주석의 그 후속이 지금.

### 3. 주간 신설 · 주 2회 제한 · 생일 절기 달력 배치

- clock에 주(week) 상태를 만들지 않는다 — `week = (day - 1) / 7` **순수 파생**(S7 무상태 날씨 관례). 선물 제한 = 인당 **주 2회 + 생일 예외**(스타듀 동형). Affinity에 주간 카운터 1개 추가(세이브 가법 키).
- **생일 ×8 배율**(주 제한 무관). affinity 보유 9인의 생일을 절기 달력(28일×4)에 배치 — 기존 행사 점유일(테마 데이 4×25일·절기 행사 12/20/16/15일)만 회피하면 26일/절기가 비어 충돌 없음. 달력 패널에 `birthday` 마커 1키 추가(T8 구조가 칸 파생이라 가법). **잠정 배치 후 실제 인물 생일 차용은 owner 협의 큐**(ADR-0032 §6).

### 4. 활동→하트 채널 실장 (메인 3인 한정)

ADR-0032 "선물·대화·활동이 모두 채운다"의 활동 축을 실장한다 — 현행 코드는 선물+대화+의뢰뿐. **자기 도메인 실적이 소량 적립**(잠정): 미호=수확 액션당 +1점 · 멜=서빙 매출 100냥당 +1점 · 바나=나락 잡귀 처치당 +1점, **각 일일 캡 12점**(일일 대화 8점과 병렬 규모 — 활동이 선물을 압도하지 않게). 서브 주민은 무채널(§6.1 "쉼터" 결 보존 — 성과 요구 0).

### 5. 단계 관문 프레임워크 + deed 게이트 (서사 내용은 S9)

- **진급 게이트 신설:** 점수가 만충해도 하트가 자동 진급하지 않는다 — ♡0~3은 **단계 관문 이벤트**(그 캐릭터와 특정 장소 대화 트리거), ♡4~5는 **의지 시험**(§6.1). S8은 **골격만**: 비트 원장(seen 플래그·세이브 가법)+게이트 판정+**placeholder 발화 1줄** — 컷신·대사 본문은 Slice 9 서사 소관(ADR-0005 "활동 시스템은 플롯 글쓰기에 비의존" — placeholder로 전 파이프라인이 플레이 가능해야 함).
- **메인 3인 관문 = deed 문턱 AND**(ADR-0032 §1): `deed.gd` 순수 판정(기존 원장 **읽기 전용** — 신규 원장 0):
  - 미호 = 누적 수확 `_run_harvested` — ♡1:30 / ♡2:80 / ♡3:160 / ♡4:300 (잠정)
  - 멜 = 누적 서빙 매출 `_cafe_revenue_total` — ♡1:500 / ♡2:1,500 / ♡3:3,500 / ♡4:7,000냥 (잠정)
  - 바나 = ♡1:갱도 10층(`mine_depth`) / ♡2:combat XP 200 / ♡3:나락 개방(`narak_key_found`) / ♡4:`_narak_best_boss`≥10 (잠정 — "S8 바나 도메인이 읽을 진척 축" 예약 주석 이행)
- 하트 **점수** 자체는 잠그지 않는다(스타듀에도 "이벤트 미시청 잠금" 없음을 미러로 확증) — 잠기는 건 **칸 진급**뿐이며 점수는 만충 상태로 대기.

### 6. 연애(♡5) = 의지 시험 + 단일 슬롯

- ♡4 만충 + 관문·deed 통과 후 **의지 시험 = 인-픽션 고백 선택**으로 연애 개시(스타듀 꽃다발 같은 별도 아이템 없음 — §6.3 "♡ max → 연애 개시"에 아이템 미규정, 슬롯 구조가 배타성 담당).
- **연애 슬롯은 전 로스터 공유 단 1개**(ADR-0032 §3). 연애 중 두 번째 시도 = **인-픽션 거절**(침묵 아님). S8 콘텐츠 개통은 메인 3인만 — T1 주민 연애·결혼은 캐릭터 묶음(초상화+대사+아크)이라 S9 점진(ADR-0014 완화책).

### 7. 질투 = 1회성 찌릿함 + 자동 회복

연애 개시 순간 1회, 안 뽑힌 메인 2인에게 **−30점(반 칸), 7일 후 자동 복원**(원장 타이머 — 영구 손실 0). 일상 선물 질투 0 · 스타듀 그룹 냉대(1주 선물 거부·분노)는 기각 확정 재확인(ADR-0032 §3). "서운함→응원" 대사 비트는 S9.

### 8. 결혼 = 정표(혼례 부적) + 배우자 방 + [메인] 속죄 아크

- **조건(§6.3 티어별):** 연애 상태 + **정표 = 옥자의 소울-바인딩 혼례 부적**(옥자에게 의뢰 — 잠정 5,000냥, 스타듀 펜던트 동가) + **배우자 방**(목공방 프로젝트 「안방 확장」 신설 — 잠정 10,000냥+원목 300·2일; carpenter.gd "방=결혼 Slice 8" 서랍의 이행, 데이터 1건+HOME 방 rect 확장+home_deco bounds 재주입) + **[메인 한정] 속죄 아크 완료**(♡ 비트 원장 참조 — S8은 placeholder 관문이라 자연 통과, S9가 내용을 주입해도 판정식 불변).
- 수락 **3일 후 아침 결혼식**(간이 연출 — 연출 등급은 S9). 결혼 = 해방(ADR-0014)의 상태 전이만 S8 소관.
- 결혼 후: 배우자 **HOME 이주**(스케줄에 HOME 스테이션 추가 — resident 스케줄 배열 1항목) · 선물 **주 2회 제한 해제**(하루 1회 유지).

### 9. 배우자 잡일 = 도메인 분화 (스타듀 균일 잡일 기각)

스타듀 배우자는 누구든 물주기·먹이를 균일 제공한다 — 이대로면 미호의 자동화 결과 중복되고, 멜·바나가 미호 도메인을 무료 제공해 **캐릭터별 곱셈기 차별화(ADR-0008)가 무너진다**(위키 대조가 적발한 ADR-0032 §6 "일괄 채택"의 맹점 — §6을 부분 개정). **각자 자기 도메인 결 1종**(잠정): 미호=아침 미급수 밭 8칸 물주기 · 멜=출하 정산 팁 +2% · 바나=밤 약탈 추가 감쇄(bana_guard 위 소폭). 여우불(성장 가속)과 물주기(노동 대행)는 별축이라 중복 아님. 그 외는 일일 대사·가끔 요리 선물로 경량.

### 10. 이혼 = ADR-0022 이행 (최소 구현)

옥자(부적을 푸는 거울 해소자)에게 의뢰 — 잠정 50,000냥. ♡0 리셋 · **적대 없음**(씁쓸·우호) · 해방 불가역 · 재구애 가능(본 비트 재지급 없음 — 비트 원장이 이혼에도 잔존) · **재혼 = ♡5 재도달 + 정표 재수여만**(배우자 방·해방 면제, ADR-0022 확정). 슬롯 해제 수단이 없으면 "두 번째 연애는 이혼 후에만"이 죽은 문장이 되므로 S8 포함. 연출은 스텁(S9).

### 11. 관계 탭 재설계 — 표시 자격 분리 + 스크롤

- **표시 자격 = 관계 트랙 보유**(`affinity != null`)로 변경 — `effect_fn`은 효과 줄 유무만 담당(이중 책임 분리). 모찌 포함 **9인 표시**(T8 이월 결함 해소·옥자/주방요괴는 설계상 무트랙이라 비표시 유지).
- **세로 스크롤 도입**(HEART_ROWS=5 고정 폐지) — **옹이 6행 무경고 유실 실버그 봉합**(inv_frame.gd:197 vs `_heart_rows()` 6행). 렌더 층 단언 추가(기존 테스트는 데이터 층만 봐서 통과하던 함정).
- 진급 대기(점수 만충·관문 미통과)·연애·결혼 상태 배지 표시.

### 12. 도메인 당근 실장 + 스코프 아웃 명시

- **ADR-0029 표와 코드의 격차 봉합:** 바나 = `narak_bana_xp_mult()` 배선(빈 함수 1.0 → 잠정 1+0.05/♡, 지정된 배선점 `_gain_combat_xp`) · 미호 = **농사 XP 가속 신설**(동형 잠정 1+0.05/♡ — 현행 여우불은 성장 가속이지 XP가 아니라 문서-코드 불일치 상태였음). 멜 마진·여우불·경비·할인은 기실장 유지.
- **스코프 아웃(명시):** 옥자 무접촉(미터 없음·마일스톤 매출 대변 유지 — owner 결재 잔존) · **동행 혼 = Slice 10 롱테일**(ADR-0032 §4 "옵션 엔드게임" 명시 — 스타듀 자녀 수치는 그때 참조) · **룸메이트 서약 = 서랍**(대상 3인 중 프로스티 미구현·비인간 ♡ 트랙 정비가 선행 — 네오 선물 개방이 그 첫걸음) · NPC 일정 하트-반응성 = 서랍(아이디어만 큐: "♡N이면 카페 체류 연장") · 하트 이벤트·조각·그날밤 고백 **내용** = S9 · T1 주민 결혼 콘텐츠 = S9 점진.

## 폐기한 대안

- **(스타듀 10/14하트 이식)** — 전 시스템 5-스케일 배선 재작업 대비 이득 0. 환산으로 충분.
- **(감쇠 채택)** — ADR-0029 "감쇠 없음"·코지 톤 위반. 관계를 유지노동으로 변질.
- **(선물 입력 = 선택 UI 신설)** — 든 아이템 문법(혼백관 선례)이 기존 관례·최소 침습. 전용 UI는 과설계.
- **(하트 점수 자체 잠금)** — 진급만 잠그고 점수는 대기시키는 §6.1 구조가 상실감 없이 페이싱 달성. 스타듀도 점수 잠금 없음.
- **(연애 개시 아이템 = 꽃다발 대응물)** — §6.3이 아이템을 규정하지 않았고 슬롯 구조가 배타성을 이미 담당. 아이템 추가는 정표(혼례 부적)와 위상 혼동만 유발.
- **(스타듀 균일 배우자 잡일)** — 곱셈기 차별화 붕괴(본문 결정 9). 도메인 분화로 대체.
- **(이혼 연기)** — 단일 슬롯 구조의 해제 수단 부재로 ADR-0032 §3이 불완전해짐.

## Consequences

- **ADR-0032 §6 부분 개정:** "배우자 잡일 스타듀 디폴트 일괄 채택" → 도메인 분화(결정 9).
- **서사 바이블 §6.1 stale 확인:** "메인=활동 실적만" 절은 ADR-0032가 개정(선물·대화·활동 모두) — 문서 갱신은 S9 서사 착수 시 일괄.
- **잠정 결정 owner 큐 적재:** 선호/혐오 테이블(실제 인물 소싱 — 1순위) · 생일 배치(실제 생일 차용 협의) · deed 문턱 4×3 · 활동→하트 적립·캡 · 질투 −30/7일 · 부적 5,000냥·안방 확장 10,000냥+원목300 · 이혼 50,000냥 · XP 가속 1+0.05/♡.
- **아트 스코프(T9):** 혼례 부적·안방 확장 실내·달력 생일 마커·관계 탭 상태 배지·(서랍) 정표 연출.
- shrimp S8-T1~T10 등록. 빌드는 §4 SOP(워크트리 격리→그레이박스→아트→회귀→PR).
- **되돌리려면** 이 ADR을 새 ADR로 대체해야 한다(특히 결정 5 단계 관문 골격·결정 9 잡일 도메인 분화).
