# 0064. Slice 6 착수 — 카페 융합 메뉴·곳간·서빙 사슬 빌드 확정 (결정 12건)

- **상태:** 승인 (2026-07-31, Fable 5 자율 캠페인 self-grill — owner 큐 검토 대기)
- **관련:** [ADR-0029](./0029-cafe-relationship-stage-domain-aligned-rewards.md)(골격) · [ADR-0007] · [ADR-0009] · [ADR-0008] · [ADR-0021] · [ADR-0028] · [ADR-0032] · [ADR-0033] · CONTEXT [카페 운영]/[융합 메뉴]/[곳간]/[체키]/[주방요괴]/[단골 손님]
- **리서치 3축:** 코드 감사(Explore/opus) · 스타듀 위키 미러(opus — Cooking·Artisan·냉장고·서빙 선례·경제 위계) · 설계 문서 판독(sonnet)

## 컨텍스트

Slice 1~5로 상류 공급 4활동(농사·낚시·채집·채광)이 전부 개통됐다. 카페는 무대·서빙 1층·마일스톤 1단·출하함·멜 마진이 라이브지만, **Slice 6의 본체인 메뉴·곳간·가공·단계 사슬은 코드 위상 0**이다(문서-코드 격차 최대 슬라이스). 설계는 ADR-0029·CONTEXT에 두텁게 확정돼 있어, 이 grill은 발명이 아니라 **이행 순서와 미결 3건의 판정**이다.

스타듀 대조의 핵심 발견: **스타듀에는 "손님에게 서빙하는" 메카닉이 없고**(리조트=개폐만·영화관 간식=취향→호감도), 스타듀 요리는 품질 배수·판매 퍼크가 없어 구조적으로 돈이 안 된다(가공 설비가 항상 우월). 나라카 카페는 이 공백을 IP 코어로 채우는 것이므로 **스타듀 요리 경제를 복제하지 않고, "서빙 프리미엄"이 요리의 값을 만든다**.

## 결정

### 1. "카페 가공" = 곳간 재료 → 융합 메뉴 (개별 아티산 설비 비채택)

Slice 6의 가공은 **곳간에 적재한 산출물이 융합 메뉴로 나가는 것** 그 자체다(주방요괴=백스테이지 추상 — 설치형 가공기 없음). 스타듀식 개별 아티산 설비(케그·절임통·치즈 프레스 등)는 **이 슬라이스에서 만들지 않는다**(catalog §1-H "개별 기계 미설계" 유지). 근거: ①ADR-0029 구조가 이미 주방을 추상으로 정의 ②설치형 원장 3종(furnace·tapper·crab_pot)이 전부 실내 배치 불가(`_indoor` 거부·region 키 한계) — 카페 실내 가공기는 구조 대공사인데 IP 코어(서빙)가 아님 ③스타듀에서 가공기가 요리를 이기는 경제 구조를 나라카는 서빙 프리미엄으로 뒤집으므로 농장 가공기 축은 급하지 않다. **벌통·꿀 시너지 defer도 유지**(catalog §2-6 — "아티산 슬라이스"는 S6이 아니라 후속 서랍으로 재정의, owner 큐).

### 2. 메뉴 2단 구조 — menu_catalog.gd 신설

`menu_catalog.gd`(static 카탈로그): **기본 메뉴**(무재료·항시·저가 — 주방요괴 생산 추상) + **융합 메뉴**(시그니처 저승 산출물 **1종 1개** 차감·프리미엄 — 다중 재료 트리 없음, ADR-0007 확정). 로스터 잠정: 기본 3~4종·융합 ~12종(작물 5·물고기 2~3·채집 2·수액 1·**나락혼정 1**=최상위). **메뉴 명명은 "실제 나라카 컨셉카페 메뉴 × 저승 번안"이 정의인데 실제 메뉴판 자료가 저장소에 없다** — 잠정 명명으로 빌드하고 **owner 실제 메뉴판 대조를 큐 1순위**로 적재(raw 명칭 교체=카탈로그 문자열만). 절기 로테이션: 융합 메뉴 판매 창=시그니처 재료의 절기 창 파생(별도 달력 데이터 없음 — 작물 사멸이 곧 메뉴 로테이션, ADR-0007).

### 3. 곳간(larder) — larder.gd 신설

`shipping_bin.gd` 문법 복제(add/take_back·changed 시그널·얇은 세이브)하되 **품질 무차원 평 dict `{id: count}`**(메뉴가 품질 무영향 — catalog §1-B 확정 — 이므로 품질 중첩이 무의미). 카페 실내 고정 설비(좌표 상수·[F] 적재/회수 UI). **스타듀 냉장고의 "인벤+저장고 가상 연결" 문법은 비채택** — 곳간에 *명시적으로 적재하는 행위*가 "팔까(출하) vs 키울까(곳간)"의 선택 텍스처라(CONTEXT [곳간]), 자동 참조는 그 선택을 지운다. 용량 잠정 30·확장=카페 일구기 결(결정 7).

### 4. 주문·폴백·가격

손님 스폰 시 **결정 롤**로 희망 메뉴 선정(해금·곳간 재고 가중). 융합 재고 있으면 프리미엄 매출+곳간 차감, 없으면 **기본 메뉴 폴백 — 손님은 떠나지 않는다**(하드 실패 없음, ADR-0029). 가격 잠정: 기본 35냥(현행 정액 유지)·**융합 = 시그니처 산출물 기본가 ×2.5 반올림**(스타듀 술집 마진 ×2와 케그 ×3 사이 — 즉석 서빙 프리미엄). 멜 마진 곱셈기(♡5 ×2.0)는 그 위에 곱한다(ADR-0008 — ♡0 base 불변). 서빙 매출만 마일스톤 계상(현행 규칙 유지).

### 5. 서빙 단계 사슬 — S6은 응대→체키 2단

CONTEXT 확정 사슬(응대→체키→그림→편지) 중 **응대+체키(상업 체키)까지 이 슬라이스**. 그림·편지=후속(단순 단계 유지 확정이라 급하지 않음). 체키 미니게임=**ChekiSession 순수 상태 머신**(FishingSession 선례 1:1 — RefCounted·시드 결정적·헤드리스 검증 가능·HUD 분리). 깊이(사슬을 쏟기) vs 회전(다른 손님)의 트레이드오프가 핵심 텍스처.

### 6. 밤 바 칵테일 — 체키 뒤 순차 (동시 구현 금지 준수)

CONTEXT "낮 체키 100% 먼저 → 밤 칵테일" 확정을 태스크 순서로 이행: 체키(T5) 완료·회귀 후 칵테일(T6) 착수. CocktailSession 순수 상태 머신(믹싱/타이밍 — 액티브 결). night_bar의 잡귀 방어·바나 보호 곱셈기는 불변. **이 ADR이 체키·밤 바 규칙의 1차 ADR 출처가 된다**(종전 CONTEXT grill 기록에만 있던 위계 이례 해소 — 문서 축 지적 ④⑤).

### 7. 마일스톤 재정의 — 바나 제외·옥자 축 판정 (미결 ③ 해소)

현행 `_milestone_hearts()`=미호+멜+**바나** 합산은 ADR-0029 §4(카페-도메인 3인=옥자·미호·멜) 위반 — **바나를 게이트에서 제외**한다(바나=던전 공급으로만 연결). **옥자 축 판정: 옥자는 호감도 미터가 없는 앵커(ADR-0032)이므로 별도 미터를 신설하지 않고, 기존 "누적 서빙 매출" 축이 옥자 축을 대변한다**(옥자=카페 정체성 그 자체 — 카페 실적이 곧 옥자의 인정. 매출 축은 이미 1단 3축에 있으므로 실질 변경=하트 축을 미호+멜 2인 합으로 좁히고 문턱 하향 8→6). 2단 콘텐츠 정의: 좌석 3→5·곳간 용량 30→50·T3 익명 볼륨 증가·융합 메뉴 슬롯 확대(잠정 — 수치는 그레이박스 레버). ADR-0009의 옛 "Sprint 7 통합 재미 게이트" 언어는 **ADR-0028이 이미 폐지**했음을 여기 명시한다(별도 개정 없이 본 노트로 갈음 — 문서 축 지적 ①).

### 8. 손님 풀 — 신규 캐릭터 발명 0 (스코프 긴장 해소)

명명 단골=**현행 주민 로스터 재사용**(네오·뱃사공·옹이·모찌·풀무·무골 — T1 잔여 10인은 Slice 9 소관이라 기다리지 않는다). T3 익명 볼륨=마일스톤 진척 파생 스폰(이름·호감도 없음). **단골화=방문 가중치 원장**(서빙 이력→재방문 확률↑ — 최소 구현)이며 호감도 트랙과 분리(ADR-0017 보호 — 서빙·매출과 대화·선물은 별개 행동). 주방요괴=T3 배경 직원 1인 신설(관계·서사 트랙 없음 — CONTEXT 확정·정체는 서랍 유지).

### 9. 메뉴 소비 — 카페 판매 전용 기본·버프 서랍

메뉴 아이템=`CAT_CONSUMABLE`(색박스 폴백 기존·품질 무차원 — 인벤 `_norm_quality` 벽과 정합). 기본은 카페 판매 전용이되 **융합 메뉴 일부는 플레이어 소비 시 혼력 회복**(`energy.restore(n)` 신설 — 명부환 HP+40의 혼력 대칭). **스타듀 요리 버프 축(10종 스탯)은 비채택 서랍** — 나라카 성장은 스킬·관계 곱셈기 축이고 음식 버프는 세 번째 축 신설이라 스코프 밖.

### 10. 해금 축 — 발견 게이트·관계 게이트 0

융합 메뉴 해금=**시그니처 산출물 첫 획득**(발견 게이트 — ADR-0033 #4·희소종 모종 선례 1:1) + 상위 일부는 카페 일구기 단계. **관계 게이트 0**(ADR-0008 — 이야기만 게이팅·미호/멜 ♡는 곱셈기). 스타듀 레시피 2대 축(TV 주간 방영·호감도 우편)은 비채택 — 나라카 카페는 레시피 수집 게임이 아니라 **공급 선택 게임**이다. 옥자의 잃어버린 레시피(히든 융합 메뉴 1종, ADR-0034)는 책 시스템 소관이라 S6 밖·훅 자리만.

### 11. 코드 정비 (T1 선행 — 실버그 2건 포함)

①`_cheapest_harvest`·서빙 알림이 `CropCatalog` 조회라 **비-작물 재료가 가격 0으로 최우선 소모·알림 빈 문자열**(재료가 물고기·채집물로 넓어지는 순간 터지는 잠복 버그) — `ItemCatalog.price_of/name_of`로 교체 ②`ItemCatalog.ids_in_category()` 신설(곳간·메뉴 UI 열거) ③`energy.restore(n)` ④마일스톤 하트 재정의 배선(결정 7). 가공 원장이 필요해지면 `furnace.gd` 분 단위 문법이 원형이나 **결정 1에 따라 이 슬라이스에선 설치형 원장 신설 없음**.

### 12. 서랍 경계·문서 부채

서랍 확정: 개별 아티산 설비·벌통 꿀 시너지·서빙 사슬 3~4단(그림·편지)·음식 버프·개인 체키+앨범(이벤트 데이 의존)·**카페 이벤트 데이 자체**(절기 달력·의상 자산 축 — 후속 슬라이스)·집 업그레이드 "주방" 단계(요리 소비처가 카페로 확정됐으므로 주방 단계의 근거 재검토는 owner 큐)·어항·온실. 문서 부채: game-loops.md §2.4(밤 경비)에 역사 기록 헤더 부착(T-말 통합 때)·본 ADR이 체키/밤 바/폴백 규칙의 ADR 위계 1차 출처.
